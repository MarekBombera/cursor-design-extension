## Repo facts at plan time

- Chrome is a template string: `artboardChromeHtml.ts` (document + CSS, 194 lines) and
  `artboardChromeScript.ts` (630 lines of plain JS). Stage geometry is inlined as a source string
  (`STAGE_GEOMETRY_SOURCE`) and tested through `node:vm`. The frame runtime is a source string too
  (`ARTBOARD_CANVAS_RUNTIME_SOURCE`), injected first in each blob's `<head>` with the chrome nonce.
- Frames: one `sandbox="allow-scripts"` blob iframe per artboard (null origin). Chrome cannot reach
  frame DOM. Frame → chrome: `cd:frame-height`, `cd:frame-wheel`, matched by `event.source`.
  Chrome → frame: **none** (hub lock; 0.3 must change it, see D4).
- Writers today: the MCP process (all tools, serialized in-process by `enqueueDiskOp`), the
  `exportHandoff` command (disk lib), and the host's `initializeDefaultArtboard`
  (`src/host/artboardDisk.ts`, via `vscode.workspace.fs`, unlocked). Disk-lib writes are atomic
  (`${file}.${pid}.tmp` + rename in `writeUtf8`) but **there is no cross-process lock**. 0.3 makes
  the host a writer of `canvas.json` and `comments.json` too.
- Host watcher covers `.cursor-design/**` (200ms debounce). It also fires on `*.tmp` and any
  `.lock` file, so 0.3 must filter those (8c).
- `canvas:updated` carries one `generation` for the active artboard. `PostedCanvasFrame` has no
  per-frame generation or hash; 8c adds them.
- `deps.alwaysBundle` in `vite.config.ts` lists only `@modelcontextprotocol/server` and `zod`. Any
  new runtime dependency of the MCP process or host must be added there, or the `.vsix` (shipped
  without `node_modules`) breaks while F5 still works.
- The lint `vscode` import ban covers `src/disk/**` and `src/mcp/**` only. `src/webview/**` needs
  its own override (8a).
- `src/disk/layout.ts` has no imports, so the webview may import its constants.
- Toolchain: TypeScript **7.0.2** (Go port), Vite+ 1.3.0 (Vite 8 / Rolldown via
  `@voidzero-dev/vite-plus-core`, tsdown, Vitest 5), Node 24.18. `vp check` type-checks through
  oxlint `typeAware` + `typeCheck` (tsgolint, a native binary independent of the `typescript`
  package). There is no standalone `vite` package in the lockfile.
- Latest at plan time: `svelte` 5.57.2, `@sveltejs/vite-plugin-svelte` 7.3.1 (peer `vite ^8`,
  `svelte ^5.46.4`), `svelte-check` 4.7.7 (peer `typescript ^5 || ^6`), `@medv/finder` 4.0.2,
  `parse5` 8.0.1, `parse5-htmlparser2-tree-adapter` 8.0.1 (`domhandler ^6`), `css-select` 7.0.0
  (`domhandler ^6`). Adapter 8.0.0 uses `domhandler ^5`: do not use it.

## Decisions (Bombic, 2026-10-21)

These override the Notion page where they differ. Projects Manager updates Notion (Contracts →
Library, Comment mode, No stale references) to match.

- **D1 Drag/resize is in-house. No Moveable.** Moveable has not shipped since `0.53.0`
  (2023-12-03) and pulls ~60 transitive deps. 0.3 needs a drag on the label and one right-edge
  handle, snapped to 8px, under a stage that is already CSS-scaled: Pointer Events with
  `setPointerCapture`, reusing `screenToStage` from `stageGeometry`. 0.4's selection outlines
  decide their own approach then.
- **D2 Stale = the comment's own element changed.** Each comment keeps the artboard version (it
  stays in the prompt), plus a fingerprint: the hash of its target's static `outerHTML`
  (whitespace-collapsed), taken at creation. `stale` is true only when that fingerprint differs at
  `get_comment`. Edits elsewhere in the file (including the Agent fixing another comment) do not
  make it stale. A selector that now matches a different element (a card inserted before it)
  changes the fingerprint, so that is still caught.
  - Known ceiling: a container target (a section, or a parent picked with ↑) includes its
    descendants, so fixing a nested comment marks the container stale. `get_comment` says so in
    its hint. `ponytail:` hash of `outerHTML`; upgrade path is hashing own tag + attributes + text.
  - **Page comments (decided by Bombic 2026-10-26, 8e):** never stale (`stale: false`);
    `targetMissing` only when the frame's HTML file is gone. A generation rule would stall Copy all
    open after the Agent fixes any other comment on the same frame.
- **D3 Keys.**
  - Before typing (popover open, comment box empty): Alt+click or ↑ moves the target to the
    parent; ↓ moves back to the child it came from.
  - In the comment box: Enter adds the comment, Shift+Enter makes a newline, Esc cancels.
  - This replaces the spec's "Shift+Enter steps up to the parent".
- **D4 Chrome → frame messages (hub lock change, 8d1).** Comment mode, parent/child stepping and
  pins that follow elements all need chrome to talk to the frame runtime. New typed messages
  `cd:mode`, `cd:pick-parent`, `cd:pick-child`, `cd:anchors`. The runtime accepts them only from
  the `parent` it captured at load. Projects Manager updates the hub "Host ↔ webview" lines after 8d1.

```txt

  main.ts                        mount(App)
  App.svelte                     container: owns bridge state, renders views
  hostBridge.svelte.ts           acquireVsCodeApi once, message listener, validation, setState
  hostMessages.ts                pure parsers for host → chrome messages (+ test)
  Toolbar.svelte, Banners.svelte, Stage.svelte, Frame.svelte
  Overlay.svelte                 screen-space layer: hover outline, pins (pointer-events: none)
  CommentPopover.svelte, CommentsPanel.svelte
  stageGeometry.ts               real TS exports (was a source string)
  stampArtboardHtml.ts           DOMParser stamp; runtime source passed in as a parameter (+ test)
  frame/
    runtime.ts                   frame runtime, bundled to an IIFE string (virtual module)
    pickTarget.ts, pickPath.ts   pure hit-stack and parent/child rules (+ tests)
    selector.ts                  finder config, text, styles, sanitizers (+ happy-dom round-trip test)
    frameMessages.ts             cd:* type names + payload guards, shared by chrome and runtime
src/disk/layout.ts               + comment caps (selector 1000, text 200, body, count, style keys)
src/disk/comments.ts             comments.json CRUD, status machine, flags (+ test)
src/disk/commentTarget.ts        parse5 + css-select match and fingerprint, cached by html hash (+ test)
src/disk/workspaceLock.ts        cross-process lock for read-modify-write (+ test)
src/mcp/commentTools.ts          list_comments, get_comment, resolve_comment
src/host/commentPrompt.ts        locked prompt + batch prompt builders (+ literal test)
src/host/chromeMessages.ts       zod/mini parsers for chrome → host messages (+ test)
```

Caps are defined once in `layout.ts` and imported by `frameMessages.ts`, `hostMessages.ts`,
`chromeMessages.ts` and `comments.ts` (rule 04). The runtime's text excerpt uses the same cap.

Message contract after 0.3. Rule 02 is updated in the same change that adds each message (8c,
8d1, 8f1, 8h), never deferred:

- chrome → host: `artboard:ready`, `frame:place {id, x, y, width, base: {x, y, width}}`,
  `comment:create {frameId, generation, selector, tagName, text, rect, point, styles, isPage}`,
  `comment:reply {id, body}`, `comment:set-status {id, status: 'open'|'resolved'}`,
  `comment:copy {id}`, `comment:copy-open`.
- host → chrome: `canvas:updated` (each frame now carries `generation` and `hash`),
  `artboard:error`, `ui:status`, `comments:updated {comments, error?}` (each comment with
  host-computed `stale`, `targetMissing`; `error` is safe copy with a relative path),
  `ui:copied {count}`, `ui:error {message}` (clipboard and comment write failures).
- frame → chrome (untrusted, matched by `event.source`): `cd:frame-height`, `cd:frame-wheel`,
  `cd:ready`, `cd:hover {rect|null}`, `cd:pick {selector, tagName, text, rect, point, styles, isPage}`,
  `cd:anchor-rects {rects: {id: rect|null}}`, `cd:key {key: 'c'|'Escape'}`.
- chrome → frame (new, D4): `cd:mode {mode: 'interact'|'comment'}`, `cd:pick-parent`,
  `cd:pick-child`, `cd:anchors {anchors: [{id, selector}]}`.

Everything from a frame is untrusted. A design's own script can post any `cd:*` message. Chrome
and host reject selectors with control characters or newlines, selectors that fail to parse,
style keys outside the allowlist, style values outside `[\w\s#%.,()'"/-]`, and non-finite or
out-of-range numbers. `commentPrompt` sanitizes `{selector}`, `{styles}` and `{text}` before they
reach an Agent prompt (rule 02 gets this note in 8d1).

## Comment status machine (8e owns it)

| From | Action | To | Who |
|---|---|---|---|
| open | Copy / Copy all open | sent | host, only if still `open` under the lock |
| open, sent | Resolve | resolved | user (chrome) or Agent (`resolve_comment` with note) |
| resolved | Reopen | open | user |
| any | Reply | unchanged | user or Agent |

`comment:set-status` from chrome accepts only `open` and `resolved`; `sent` comes only from the
copy path. `resolve_comment` on a resolved comment is `isError` `COMMENT_RESOLVED`. A copy racing
an Agent resolve leaves `resolved`.

## Error surfaces (rule 06)

| Failure | Typed error / code | UI | MCP |
|---|---|---|---|
| `comments.json` corrupt | `CorruptCommentsError` | `comments:updated {error}` banner; frames stay rendered; file never overwritten | `isError`: fix or delete the file |
| `comments.json` newer version | `UnsupportedCommentsVersionError` | same banner, update the extension | `isError` |
| `comments.json` missing | none: empty list | none | empty list |
| comment id unknown | `CommentNotFoundError` (`COMMENT_NOT_FOUND`) | `ui:error`, refresh | `isError`: call `list_comments` |
| resolve twice | `CommentResolvedError` (`COMMENT_RESOLVED`) | n/a | `isError` |
| lock busy past timeout | `LockTimeoutError` (`WORKSPACE_BUSY`) | `artboard:error` / `ui:error`: try again | `isError`: retry the call |
| frame moved by the Agent since drag start | `ConflictError` (existing) | drag reverts to disk | n/a |
| artboard changed since the pick | `ConflictError` | `ui:error`: pick again | n/a |
| clipboard write fails | logged | `ui:error`; statuses unchanged | n/a |
| untrusted workspace | refused | comment mode and drag disabled | existing behavior |

Every failure is logged once with `logDiskError` (host) or `logMcpError` (MCP). No stack or
absolute path in UI or MCP text.

## 8c. Frame drag and resize (M)

Goal: Notion done-when "drag by label, resize width, persists" and "Agent place_frame during or
after a drag is reflected". In-house per D1; no drag/resize library.

1. `src/disk/workspaceLock.ts`: `withWorkspaceLock(workspaceRoot, operation)`.
   - `mkdir -p .cursor-design/` first, then create `.cursor-design/.lock` with `open(..., 'wx')`,
     writing pid + timestamp. Retry with short jittered backoff up to 2s, then throw
     `LockTimeoutError` (`WORKSPACE_BUSY`).
   - Stale break: a lock older than 30s is broken by atomic `rename` of the observed lock to a
     unique `.lock.stale.<pid>.<random>` name, then deleting that file and retrying `wx`. Only the
     process whose rename succeeds breaks it, so two waiters cannot both hold the lock.
   - Only the single-file read-modify-write runs under the lock (read JSON, change, `writeUtf8`).
     Anything slower (listing artboards, reading HTML) runs before or after. That keeps holds far
     below the 30s stale age without a heartbeat. `ponytail:` mtime stale break, no PID liveness.
   - Wrap `placeFrame`'s canvas read-modify-write. MCP keeps `enqueueDiskOp` on top.
   - Host watcher callback ignores `.lock*` and `*.tmp` paths.
2. Per-frame `generation` and `hash` added to `PostedCanvasFrame` / `canvas:updated` (needed for
   8c conflicts and 8f creation). Rule 02 updated in this change.
3. Label gets `pointer-events: auto`, `cursor: move`, and a right-edge handle element per frame
   (fixed screen width). Pointer capture on the dragged element. Both are inert in comment mode.
4. Pure helpers in `stageGeometry.ts`. Contracts:
   - `dragFrame({start, pointerDelta, zoom})`: new x/y = `snapToGrid(start + pointerDelta / zoom, 8)`,
     snapping the absolute stage position, not the delta.
   - `resizeFrameWidth({start, pointerDelta, zoom})`: width = `snapToGrid(start.width + delta / zoom, 8)`
     clamped to `MIN/MAX_FRAME_WIDTH` from `layout.ts`. Width is snapped, not the right edge.
   - The disk lib's clamp stays authoritative; chrome clamps only for the preview.
5. While dragging, chrome renders a local override; one
   `frame:place {id, x, y, width, base: {x, y, width}}` on pointer-up (only if changed). Escape
   cancels. Host parses with zod/mini (`src/host/chromeMessages.ts`): finite numbers, x/y within
   ±100000, width any finite number (disk lib clamps). Refuses in untrusted workspaces. Under the
   lock, if disk x/y/width differ from `base`, it writes nothing and posts `artboard:error`
   ("The Agent moved this frame; showing its position"). Chrome drops the override on any
   `artboard:error` or `canvas:updated` for that frame.
6. Agent wins mid-drag: if `canvas:updated` arrives during the drag with a different x/y/width for
   the dragged frame than at drag start, cancel the drag and render disk. The `base` check covers
   the window between the last refresh and pointer-up.
7. Keyboard: the label is focusable; arrow keys nudge 8px (Shift: 64px), committed on keyup.
8. Height stays content-driven; nothing writes height.

Edge-case tests:
- lock: stale lock with an old mtime (`utimes`) is broken and the op proceeds; a live lock held
  past the retry window gives `LockTimeoutError`; a lock held longer than the timeout but younger
  than the stale age is not broken; two spawned `node` children hammering `placeFrame` all land;
  a child killed mid-hold leaves a lock that the next op recovers after the stale age; two
  waiters racing to break the same stale lock end with exactly one holder; `.cursor-design/`
  missing is created. (unit)
- geometry: width 119/120/3840/3841 through `resizeFrameWidth` and the disk path; negative x/y;
  1e308, NaN, Infinity rejected by `chromeMessages`; snap at zoom 0.05, 1, 4; resize with x not a
  multiple of 8. (unit + property)
- host handler: `base` mismatch writes nothing and returns the conflict; unchanged position sends
  no message. (unit)
- F5: drag over an iframe keeps capture; Escape cancels; Agent `place_frame` mid-drag wins; failed
  write reverts the override.

## 8d1. Frame runtime channel + picking (M, Bombic priority)

Goal: the first half of Notion "Element picking must feel precise". No comment storage yet. The
chrome shows the current pick (selector chip and outline) so it can be judged in F5; no logging
(`console` is lint-banned).

1. New chrome → frame channel (D4). Runtime accepts only `event.source === capturedParent`, typed
   and validated. Runtime posts `cd:ready` once listeners are in place; chrome then sends
   `cd:mode` and `cd:anchors`. Rule 02 updated in this change (messages, untrusted-input note).
2. Comment mode inside the frame: capture-phase listeners on `window` (registered by the runtime
   before any artboard script) for `pointerdown`, `pointerup`, `mousedown`, `mouseup`, `click`,
   `dblclick`, `auxclick`, `contextmenu`, `submit`, plus `keydown` Enter/Space on focusables:
   `preventDefault()` + `stopImmediatePropagation()`. Interact mode early-returns.
3. Hit testing, `pointermove` throttled to one `requestAnimationFrame`:
   `document.elementsFromPoint(x, y)` → `pickTarget(stack)`:
   - `pointer-events: none` layers are already absent from the stack (native).
   - **Transparent overlay rule:** skip an element that paints nothing itself (transparent
     background, no border, no shadow, no own text node, not `img/svg/video/canvas/input/...`) when
     some element further down the stack is not its ancestor. A transparent wrapper whose stack
     below is only its ancestors is kept.
   - SVG internals resolve to the outermost `<svg>`.
   - Nothing but `html`/`body` → page comment (`isPage: true`, selector `body`).
   - Alt+click → parent of the picked element.
   `pickTarget` takes the stack plus `paints(el)` / `contains(a, b)` predicates so it is pure.
4. Parent/child stepping (D3) in pure `pickPath.ts`: `cd:pick-parent` pushes the parent (stops at
   `body`), `cd:pick-child` pops toward the clicked element, a new click resets. Each step posts a
   fresh `cd:pick`.
5. Hover and pick rects are frame-local; chrome maps with `frame.x + rect.x`, then
   `stageToScreen`, and draws in a screen-space `Overlay` (`pointer-events: none`). A capture
   `scroll` listener re-posts the hover rect. Rects are clipped to the nearest scrolling ancestor;
   a target scrolled out of view posts `null`.
6. Untrusted sizes: chrome drops `cd:*` payloads that fail the guards in `frameMessages.ts` (caps
   from `layout.ts`, finite rects, allowlisted `cd:key` values).

Edge-case tests (unit, pure helpers; happy-dom only where a DOM is needed):
- `pickTarget`: overlay skipped; transparent section kept; SVG path → svg; empty stack → page;
  transparent element covering a sibling skipped; zero-size element.
- `pickPath`: up, up, down returns the first parent; down at the bottom stays; up at `body` stays;
  new click resets; parent of a removed node.
- message guards: selector over 1000, control characters, non-finite rect, extra style keys,
  wrong `event.source` (another frame spoofing `cd:anchors` for a sibling), `cd:key` outside the
  allowlist.
- F5 fixture `fixtures/dev-workspace/.cursor-design/artboards/picking.html`: nested, repeated,
  scrolled, transparent overlay, `pointer-events: none` layer, absolute badge, 8px icon, SVG, a
  script-generated element, a `<video controls>`, a nested `<iframe>`. Hover == click target at
  10%, 100%, 400%; links, buttons and forms never fire in comment mode.

## 8d2. Selectors (S)

Goal: second half of picking: stable, unique selectors and the data a comment stores.

1. `selector.ts`: `finder(el, { root: document.body, idName, className, attr, timeoutMs })` with
   filters that drop generated names (hash-like `css-1x2y3z`, `svelte-abc123`, ids with 6+
   digits). Text: `innerText` whitespace-collapsed, cut to the shared cap. `tagName` lowercased.
   Styles: allowlist of computed props (`font-family`, `font-size`, `font-weight`, `line-height`,
   `color`, `background-color`, `padding`, `margin`, `border-radius`, `display`, `width`,
   `height`, `gap`), values sanitized. Rect: frame-local CSS px from `getBoundingClientRect`.
2. `cd:pick` carries `{selector, tagName, text, rect, point, styles, isPage}`.

Edge-case tests (happy-dom, colocated):
- round trip on the picking fixture: nested sections; five identical cards (pick #3 →
  `querySelectorAll(sel)` is exactly that card); scrolled box; duplicate ids; escaped ids;
  hash-like class names ignored; svg internals; shadow-DOM host; `<template>` content; element
  removed after pick.
- script-mutated DOM: a script inserts a sibling before the target, so `:nth-child` differs from
  the static HTML (feeds the 8e cross-check).
- sanitizers: control characters, newlines, oversized values, disallowed style keys.

## 8e. Comments on disk + MCP tools (M)

Goal: `comments.json`, `list_comments`, `get_comment`, `resolve_comment`. No UI. Starts after 8c
(lock) and 8d2 (selector fixture). Confirm the page-comment stale rule (D2) and the batch prompt
wording (8h) with Bombic before the spec.

1. Layout: `COMMENTS_FILE = 'comments.json'`, `COMMENTS_SCHEMA_VERSION = 1`,
   `commentsPathSegments`, caps (body, text, selector, comment count, reply count) in `layout.ts`.
2. Shape (zod/mini parser + serializer, `parseCommentsFile`). `artboard` = the artboard title at
   creation, with the canvas label fallback (empty or missing title gives the frame id; Bombic
   2026-10-26):
   `{ version: 1, comments: [{ id, frameId, artboard, selector, tagName, text, rect, pin: {x, y},
   styles, body, replies: [{ id, author: 'user'|'agent', body, createdAt }],
   status: 'open'|'sent'|'resolved', createdAt, version, targetFingerprint?, isPage }] }`.
   `pin` is a 0–1 fraction of the target rect (page comments: of the frame width and height), so
   pins follow the element and survive frame resizes. Duplicate ids are a parse error.
3. `commentTarget.ts`: `matchCommentTarget({ html, selector })` →
   `{ matches: number, tagName?, text?, fingerprint? }`, fingerprint = `hashHtml` of the match's
   whitespace-collapsed `outerHTML`. Parse each artboard once per refresh and cache by artboard
   hash + selector. Add `parse5`, `parse5-htmlparser2-tree-adapter`, `css-select` to
   `deps.alwaysBundle`; record the `dist/mcp.js` size before and after in this file.
   **Recorded (8e):** minified (`pnpm package`) 460,118 → 663,603 bytes (+203 kB, under the
   300 kB gate); unminified (`pnpm compile`) 943,667 → 1,323,726 bytes.
4. `comments.ts` ops, each read-modify-write inside `withWorkspaceLock` + atomic `writeUtf8`:
   `addComment`, `replyToComment`, `setCommentStatus` (status machine above),
   `markCommentsSent(ids)` (only those still `open`), `resolveComment(id, note)`,
   `listComments({status})`, `getComment(id)`. A corrupt or newer-version file is never written.
5. Ceiling (8e): the tag + text cross-check cannot tell identical-looking siblings apart, so a
   script-inserted twin can be fingerprinted instead (same content, so usually harmless).
   Creation (host, `comment:create`): under the lock, if the frame's disk generation differs from
   the message's `generation`, reject with `ConflictError` ("The artboard changed; pick again").
   Static match must have the same `tagName` and a text prefix match; otherwise store no
   `targetFingerprint` and flag the comment script-affected. 0 or 2+ static matches: no
   fingerprint, script-affected.
6. Flags (one function `commentFlags`, used by MCP and host; computed only when `comments.json` or
   that artboard's hash changed):
   - `targetMissing`: frame file gone, or selector matches 0 or 2+ elements now.
   - `stale` (D2): fingerprint changed. Page comments: frame generation differs from `version`
     (pending Bombic).
   - Script-affected (no fingerprint): `targetMissing: null`, `stale: null`, hint "target is
     generated or changed by script; cannot check it from disk". Reported, never guessed.
   - Container hint (D2 ceiling) in `get_comment` when the target has descendants.
7. Errors in `errors.ts`: `CommentNotFoundError`, `CommentResolvedError`, `CorruptCommentsError`,
   `UnsupportedCommentsVersionError`, `LockTimeoutError` (if not added in 8c). Messages name the
   next step ("Call list_comments({status: 'open'})").
8. **Moved to 8f1** (the first feature with a consumer; 8e ships no host or chrome change).
   Host read path: comments load in their own try/catch, separate from the canvas snapshot, so a
   bad `comments.json` never blanks the stage (`loadActiveSnapshot` returns an empty snapshot on
   any error today). Failure → `comments:updated {comments: [], error}`.
9. MCP: tool names in `toolNames.ts`; handlers in `src/mcp/commentTools.ts`, each accepting
   `rootPath` and running through `runQueued` like the artboard tools (multi-root behaves the
   same). `list_comments` never returns resolved unless asked. Rule 02 tool list and the shipped
   `cursor-design` skill (`skills/cursor-design/SKILL.md`, which replaced
   `cursor-design-agent-loop` in 8e) updated in this change.

Edge-case tests (unit; contract tests through `InMemoryTransport`):
- `comments.json`: missing, empty file, `{}`, `version: 2`, non-array `comments`, duplicate ids,
  oversized body, over the count cap, unknown fields dropped.
- fingerprint: whitespace-only reformat stays fresh; edit inside the target → stale; edit
  elsewhere → fresh; nested comment fixed inside a container → stale with the container hint;
  card inserted before → selector hits another element → stale; 0 and 2+ matches → missing.
- creation cross-check: tag mismatch and text mismatch → script-affected; generation mismatch →
  conflict, nothing written.
- status machine: resolve on resolved errors; `sent` from chrome rejected; reopen; copy racing an
  Agent `resolve_comment` leaves `resolved`.
- contract: each tool's happy path, not-found, resolved, `status` filter, missing `rootPath` in
  multi-root, corrupt file `isError` with the next step; no stack or absolute path in any text.
- export and handoff byte-identical with and without `comments.json`; no comment data in export.
- cross-library round trip: finder selector from happy-dom on the picking fixture matches exactly
  one element in `matchCommentTarget` (happy-dom vs parse5, not a real browser; F5 covers that).
- `.vsix` smoke: `dist/mcp.js` runs `get_comment` without `node_modules`. (manual)

## 8f1. Comment mode + popover (M)

Goal: Notion "C toggles Comment mode", "Adding a comment writes comments.json". Rule 08 Svelte
workflow on every component edit.

1. Mode toggle in the toolbar (`aria-pressed`), `C` key in chrome and forwarded from frames as
   `cd:key` (runtime ignores keys from editable targets and with Cmd/Ctrl/Alt), Escape closes the
   popover then exits the mode. Hint "Click to comment." Disabled in untrusted workspaces.
2. Click → `cd:pick` → popover anchored at the pick point (screen space, flips at viewport edges),
   target chip (element text or "Whole frame"), textarea, Add comment, Cancel. Focus moves to the
   textarea and returns to the stage on close. Keys (D3):
   - Comment box empty: ↑ sends `cd:pick-parent`, ↓ sends `cd:pick-child`; the outline and chip
     update from the new `cd:pick`. Once the box has text, arrows move the caret.
   - Enter adds the comment (ignored while empty or during IME composition, `event.isComposing`).
     Shift+Enter inserts a newline. Esc cancels; a second Esc leaves Comment mode.
   - The chip shows "↑ parent · ↓ child".
3. Add → `comment:create {frameId, generation, ...pick}` → host validates (caps, sanitizers),
   stamps `id` (`randomUUID`), `createdAt`, `version`, fingerprint → `addComment` → watcher
   refresh posts `comments:updated`. A `canvas:updated` for that frame while the popover is open
   keeps the popover and the typed text; creation then hits the generation check and asks to
   pick again.
4. Panel replay: `comments:updated` and `ui:*` go through the same `chromeReady` / pending replay
   and `reloadVisibleArtboardFromDisk` path as `canvas:updated`. The router refuses in untrusted
   workspaces and rejects unknown ids with safe copy.

Edge-case tests: pure key handling (empty vs typed box, IME, Esc twice, modifier keys) and
`chromeMessages` caps (unit). F5: popover flips at edges; new frame added while in comment mode
gets `cd:mode`; frame reload resends `cd:ready` → `cd:mode` + `cd:anchors`.

## 8f2. Pins that follow elements (M)

Goal: Notion pins follow elements, page comments, pin states.

1. Chrome sends `cd:anchors` per frame on `cd:ready` and on every `comments:updated`. Runtime
   resolves selectors and re-measures on: `ResizeObserver` on targets and the root, capture
   `scroll`, `MutationObserver` on `body` (subtree), capture `load` (images), `document.fonts.ready`,
   `transitionend` / `animationend`. One measurement per animation frame at most; post
   `cd:anchor-rects` only when a rect moved by more than 0.5px.
2. Pin = rect origin + `pin` fraction, drawn in the screen-space overlay at constant size, hidden
   when the target is clipped out by a scrolling ancestor. `null` rect → pin at the stored `rect`
   with a "target missing" badge.
3. Pin states: open, sent, resolved (dimmed) look different; stale gets a warning badge;
   script-affected gets an "unchecked" badge. Pins are buttons (`aria-label` with a body excerpt);
   click opens the thread popover with Reply, Resolve/Reopen, Copy.
4. Page comments: pin at the stored fraction of the frame.

Edge-case tests: pin fraction math with a zero-size target (no NaN), rect epsilon filter (unit).
F5: target removed, scrolled out of its box, image and font load shift, animated element, frame
resized by drag, frame reload.
