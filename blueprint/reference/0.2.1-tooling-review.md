# 0.2.1 Tooling - plan review findings

Source brief: Notion [0.2.1 — Tooling](https://app.notion.com/p/3fd500344e088166afe5e9295bf601fc) (2026-10-18).
Reviewed 2026-10-19 against `main` at `49c2d37` (independent plan review of the 7a-7h split).
Every `/feature` for 7a-7h must read the section for its item and carry the relevant
checks into its build steps. Rule for the whole release: **no product behavior changes.**

## Repo facts at review time

- Bundle: `esbuild.js`, two CJS entries. `src/extension.ts` -> `dist/extension.js` with
  `external: ['vscode']`. `src/mcp/server.ts` -> `dist/mcp.js` with
  `define process.env.CURSOR_DESIGN_VERSION` from `package.json` (mcp only). Dev = sourcemaps,
  `--production` = minify. `.vscodeignore` excludes `**/*.map`, `esbuild.js`, rc files.
- Runtime deps `@modelcontextprotocol/server` (v2, ESM, `/stdio` subpath) and `zod` must be
  inside the bundle: the `.vsix` is built with `--no-dependencies` and ships no `node_modules`.
- Unit tests: 13 `src/**/*.test.ts` files, 178 tests, all `import { test, afterEach } from 'node:test'`
  plus `node:assert`. Only runner is undeclared:
  `tsc -p . --outDir out && node --test out/disk/*.test.js out/mcp/*.test.js out/panel/*.test.js`.
- `pnpm test` = `vscode-test`, which runs only `out/test/**/*.test.js` (the sample mocha test in
  `src/test/extension.test.ts`). **None of the 178 tests run under `pnpm test` today.**
- `.npmrc` has `enable-pre-post-scripts = true`, so `pretest` (`compile-tests && compile && lint`) fires.
- `tsconfig.json`: `rootDir: "src"`, no `include`, `types: ["node", "mocha"]`.
- F5: `launch.json` `preLaunchTask: "compile"` -> `tasks.json` runs `pnpm compile`
  (`check-types && lint && node esbuild.js`). `watch` task depends on `npm: watch:esbuild` and
  `npm: watch:tsc`; the esbuild problem matcher greps `✘ [ERROR]`, `[watch] build started`,
  `[watch] build finished`.
- `vscode:prepublish` -> `pnpm run package` (`check-types && lint && esbuild --production`).
- `pnpm-workspace.yaml` has `allowBuilds: esbuild: true`. No `.github/`, no CI.
- No `vp` binary installed. Node 24.18, pnpm 12.10.
- Docs confirm `vp check` (oxfmt + oxlint + tsgolint), a `lint` block with type-aware options,
  and `vp pack` (tsdown). **No docs found for a `pack` block in `vite.config.ts`**; 7a must prove it.

## Findings by item

### 7a Pack spike (HIGH)

- **Parity checklist** with `esbuild.js`: two entries with different options (config array or two
  configs); `vscode` external on extension only (`deps.neverBundle`); version `define` on mcp only;
  output names exactly `dist/extension.js` / `dist/mcp.js` (`fixedExtension: false`, else `.cjs`);
  CJS format, Node platform; sourcemaps in dev, minify in production; MCP SDK + zod bundled
  (`deps.alwaysBundle`, since tsdown skips `dependencies` by default). A CJS-is-legacy warning is expected.
- **Prove it runs:** `node dist/mcp.js` completes an MCP initialize handshake over stdio;
  `unzip -l` on the built `.vsix` shows both dist files and no `node_modules`; F5 opens the panel
  and the MCP server registers.
- **F5 chain is coupled:** keep a `pnpm compile` script (AGENTS.md and the F5 task rely on it) but make
  it the fast build. Do not make F5 depend on `vp check`, or lint/format warnings block F5.
- **Watch matcher:** the `watch` task's background matcher must be rewritten against tsdown's real
  watch output (or a tiny wrapper that prints the old markers), or F5 hangs waiting for "ready".
- **`vscode:prepublish` / `package`:** 7a owns re-pointing them to a production `vp pack`, so 7b can
  remove `check-types`/`lint` without breaking packaging.
- **tsconfig:** `vite.config.ts` is the first root-level TS file; with `rootDir: "src"` it breaks `tsc`.
  Add `include: ["src"]` and a separate config tsconfig (e.g. `tsconfig.node.json`) or drop `rootDir`.
- 7a creates `vite.config.ts` with only the `pack` part; lint/fmt blocks belong to 7b.
- Update `.vscodeignore` for new root files (`vite.config.ts`, any extra tsconfig).
- **Fail path:** keep esbuild for the bundle only and record the reason in Notion and the spec;
  later items use Vite+ for everything else.
- On pass: remove `esbuild.js`, the `esbuild` dev dep, and `allowBuilds: esbuild`.
- Pin and record the `vite-plus` version; check whether it needs pnpm `overrides`/aliases for
  `vite`/`vitest` and how that interacts with the existing `overrides` block.

### 7b vp check (MEDIUM)

- Move `.oxlintrc.json` (plugins, `correctness: error`, `curly`/`eqeqeq`/`no-throw-literal` warn,
  ignore patterns) and `.oxfmtrc.json` (semi, singleQuote, useTabs, printWidth 100, every ignore
  pattern incl. `blueprint/**`, adapter trees, `src/types/vscode.cursor.d.ts`) into `vite.config.ts`.
  Losing the `$schema` lines is fine.
- Remove `check-types`, `lint`, `lint:fix`, `fmt`, `fmt:check`, `watch:tsc` scripts, oxlint/oxfmt deps,
  both rc files, and the `watch:tsc` dependency in `tasks.json`.
- **`pretest` must be removed or rewritten** (pre/post scripts are enabled).
- `vp check` formats; any formatting drift goes in its **own commit**, separate from config changes.
- Do not enable type-aware rules here (that is 7e).

### 7c vp test (HIGH)

- Vitest config discovers `src/**/*.test.ts` and **excludes `src/test/**`** (the Electron suite).
- Rewrite the 13 files' `node:test` imports to Vitest (`test`, `afterEach`, etc.); `node:assert` may stay.
  `artboardTools.test.ts` and `artboardChromeHtml.test.ts` mutate env and stub servers: check
  isolation; prefer `pool: 'forks'` and no cross-file shared state.
- `@types/mocha` must not be in the Vitest type set (collides with globals).
- Done = the same 178 tests (count recorded) pass under `vp test`; declare the Test command in AGENTS.md.
- Removing the `compile-tests`/`watch-tests` `out/` build waits for 7d's decision on the Electron suite.

### 7d Electron suite home (HIGH)

- The brief says keep `@vscode/test-electron` and remove the `out/` test build; those conflict.
  `.vscode-test.mjs` points at `out/test/**/*.test.js`. Pick one: bundle `src/test/*.test.ts` as a
  separate entry, or keep a minimal `tsc -p tsconfig.test.json --outDir out` only for that suite.
- Decide whether `src/test/extension.test.ts` (sample, asserts nothing product-specific) stays.
- Then remove whatever is now dead: `compile-tests`, `watch-tests`, `@types/mocha` from the main
  tsconfig, `@vscode/test-cli` if unused, `npm-run-all` once no `-p` scripts remain.
- The Electron suite needs a display: keep it out of the Verify/CI command.

### 7e Stricter static checks (MEDIUM)

- Type-aware lint is a config switch; the work is fixing violations. **Fixes must be pure:**
  add `void` (fire-and-forget kept as today) or `await` only where ordering is already awaited by the
  caller. Each `no-floating-promises` site must be judged; adding `await` can change timing, which
  breaks the no-behavior-change rule. Record per-site choice in the spec.
- knip needs explicit entries (`src/extension.ts`, `src/mcp/server.ts`, `src/test/**`,
  `vite.config.ts`), `vscode` as external, and must not flag `@types/vscode` or commands referenced
  only from `package.json` `contributes`. Remove only deps knip proves dead.

### 7f Test depth (MEDIUM)

- fast-check property tests: `src/panel/stageGeometry.ts` (zoom-at-cursor fixed point, clamps,
  fit-all contains every box), handoff stale check (any frame hash change, add, or remove = stale),
  zod manifest/meta round-trips (read then write gives the same bytes).
- Snapshots for generated `IMPLEMENT.md` and `canvas.html` must scrub temp paths, export ids and
  timestamps, or they will flake.
- Coverage needs `@vitest/coverage-v8`. Add a coverage script only; **no coverage thresholds**
  (not in the brief).
- Independent of 7e/7g; can run in either order after 7c.

### 7g MCP contract tests (HIGH)

- `@modelcontextprotocol/client` + the server package's `InMemoryTransport`, calling tools through
  the real server (today's tests capture handlers with a stub `registerTool`, bypassing SDK input
  validation and `isError` wrapping).
- Cover all 8 tools: `set_artboard`, `update_artboard`, `read_artboard`, `list_artboards`,
  `place_frame`, `set_active_artboard`, `export_artboard`, `handoff_status`. Assert the full
  `listTools` set so a new tool without a test fails.
- Assertions characterise **current** behavior. If the real path returns a different error than the
  stub tests (e.g. SDK "Input validation error" for a bad id shape), fix the test, not the product.
- Tool roots come from `process.env` at call time: set env per test, run serially within the file.

### 7h Verify + CI (LOW)

- One Verify command = check + test + pack (no Electron suite). Record it under Commands in AGENTS.md
  and update README dev commands.
- `.github/workflows/verify.yml` on push to `main` and pull requests, Node 24, pnpm install, a
  Vite+ install step (`vp` is its own binary), `contents: read` only.
- Final F5 smoke + `.vsix` listing: no product behavior changed.
