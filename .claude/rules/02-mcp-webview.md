# MCP + webview contracts

## MCP tools (v1), no open_artboard

- `set_artboard`: create/init; may set active / open panel
- `update_artboard`: requires `baseGeneration` and/or `baseHash`; conflict on mismatch; its read-compare-write runs under the workspace lock (`WORKSPACE_BUSY` after a 2 s wait), shared with the panel's edit and undo / redo
- `read_artboard` / `list_artboards` / `set_active_artboard`
- `export_artboard`: exports every frame to `handoff/<exportId>/` (IMPLEMENT.md, canvas.html, tokens.json, `<group>/<id>/index.html`); takes no `artboardId`
- `handoff_status`: stale when any frame's HTML changed or a frame was added or removed since the last export
- `place_frame`: one frame's x / y / width / label / group in `canvas.json`; returns every frame
- `list_comments({status})`: comments from `comments.json` with `stale` / `targetMissing` (`null` = unchecked) and `replyCount` instead of `replies`; omitted status is every unresolved comment
- `get_comment(id)`: one comment, with its replies and those flags checked against the artboard on disk
- `resolve_comment(id, note)`: resolve after changing the target; `note` is stored as an agent reply

The shipped Agent skill `skills/cursor-design/SKILL.md` documents the MCP tools, Agent-visible error codes, artboard runtime limits and workflows; changing any of them updates the skill in the same change. `src/mcp/agentSkill.test.ts` fails on tool-name, error-code and frame-width drift. The extension copies it to `~/.cursor/skills/cursor-design/` on activate (`syncAgentSkill`).

Serialize writes (`enqueueDiskOp`). `canvas.json` and `comments.json` read-modify-writes, and `updateArtboard`'s artboard HTML + meta read-compare-write, run under the cross-process `withWorkspaceLock` (`.cursor-design/.lock`), shared with the panel's drag commit, Edit-mode change (9c) and undo / redo (9f). MCP denied: edit `.cursor-design/**` directly and tell the user to allowlist the tools.

## Disk (user workspace)

`.cursor-design/`: `manifest.json`, `canvas.json`, `comments.json`, `artboards/<id>.html`, optional meta, `assets/`, `tokens.json`, `handoff/<exportId>/`. Multi-artboard + one active. No gallery. Users gitignore `.cursor-design/`.

## Webview CSP and messages

1. Never eval artboard HTML in parent chrome.
2. Nested iframe `sandbox="allow-scripts"`; artboard JS is required. The blob frame inherits the chrome CSP, so `stampArtboardHtml` puts the chrome nonce on every artboard script and style, and adds `FRAME_CSP` (inline only, no sources) first in head: a nonce'd `<script src>`, or one artboard JS injects with the nonce it read, never loads. The chrome CSP also allows style attributes (style-src-attr 'unsafe-inline'), so a style="…" attribute renders in a frame; inline on* handlers stay blocked. Changing either policy updates the shipped Agent skill.
3. Iframe-to-chrome `postMessage` is untrusted.
4. `asWebviewUri` + `localResourceRoots`.
5. Messages: artboard:ready, frame:place { id, x, y, width, base: { x, y, width } } (chrome → host, untrusted: `parseChromeMessage`, refused in untrusted workspaces, every attempt answered with one canvas:updated plus artboard:error on failure), comment:create { requestId, frameId, generation, selector, tagName, text, rect|null, point, box, styles, isPage, body } (chrome → host, untrusted: `parseChromeMessage`, then `addComment`; refused in untrusted workspaces; every attempt with a valid requestId answered once, never replayed: comment:added { requestId } or ui:error { message, requestId? }), comment:reply { requestId, id, body } and comment:set-status { requestId, id, status: open|resolved } (chrome → host, same boundary and one-answer rule, through the disk lib's `replyToComment` / `setCommentStatus`, which take the lock themselves: never wrap them; the answer is comment:saved { requestId } or ui:error, posted before the comments:updated it causes), comment:copy { requestId, id } and comment:copy-open { requestId } (8h, chrome → host, same boundary and one-answer rule; the host builds the locked prompt from disk with `commentPrompt`, writes `vscode.env.clipboard` first, and only then calls `markCommentsSent` (open only, takes the lock itself); the answer is ui:copied { requestId, count } (count = comments moved open → sent) or ui:error, and every copy answer is followed by comments:updated); artboard:edit { requestId, frameId, sourceNumber, hash, field: text|font-size|color|padding|margin, value, liveText? (iff text) } (9c, chrome → host, sent by the Edit-mode inspector since 9e: one in flight per panel, the next with the answered hash; untrusted: `parseChromeMessage` checks shape and size only, `editArtboard` checks the hash and runs the edit core; refused in untrusted workspaces; every attempt with a valid requestId answered once, never replayed: artboard:edited { requestId, frameId, hash, generation, html, canUndo, canRedo } (html = the tagged frame copy the watcher echo will post; the flags are the frame's undo history after the write, 9f) or ui:error { message, requestId }), artboard:history { requestId, frameId, step: undo|redo } (9f, chrome → host, the inspector's Undo / Redo: same boundary, queue and one-answer rule as artboard:edit; `parseChromeMessage` checks shape only, the host writes only bytes its history holds, through `updateArtboard` with the history's current hash under the lock; answered by artboard:edited (the chrome adopts it and reloads the frame) or ui:error; the history is whole-file snapshots, 20 steps per frame, in extension memory for the panel session, never on disk; a posted hash the history does not hold (an outside change), a step's conflict or a missing file clears that frame's history, the extension's own echo and a stale refresh do not), canvas:updated (frames carry `generation` and `hash`: hashHtml of the disk HTML, never the tagged copy, '' when unreadable; and `canUndo` / `canRedo`, 9f, read from the undo history when the outbox sends, a replay included) (each frame's html is the disk HTML with host-added data-cd-src="N" source numbers, sourceTags.ts; disk, export, comment flags and read_artboard never carry them)|artboard:error, ui:status, comments:updated { comments, error? } (host → chrome; each comment carries `stale` / `targetMissing` from `readComments`, `null` = unchecked; comments:updated is held until artboard:ready and re-sent on reload like canvas:updated, and its `error` is the comments banner, never a blank stage). iframe → chrome, allowlisted by source and typed (`parseFrameMessage`): cd:frame-height { height }, cd:frame-wheel { deltaX, deltaY, ctrlKey, x, y }, cd:ready, cd:hover { rect|null }, cd:pick { selector|null, tagName, text, rect|null, point, box, styles, isPage, repost, edit? } (`rect` is frame-local CSS px; `point` is CSS px relative to the current target's border box and `box` is that box's unclipped size; `repost` is true for a scroll or resize re-post, false for a click or step; `edit` { sourceNumber|null, sharedNumber, textState: plain|children|too-long, text, style|null } only in Edit mode (9d): `sharedNumber` only with a number, `text` the raw text node (at most MAX_EDIT_TEXT_CHARS, '' unless plain), `style` the style attribute ('' when absent, null only over MAX_PICK_STYLE_CHARS, 9e); chrome drops cd:hover and cd:pick in Interact mode and a cd:pick whose `edit` does not match the mode, Edit with it and Comment without, `pickCounts`), cd:key { key: c|Escape|undo|redo } (C or Escape with frame focus, not from editable targets or with Ctrl/Meta/Alt; the chrome's mode-key rule decides; undo / redo (9f) are Cmd/Ctrl+Z and Cmd/Ctrl+Shift+Z, no Alt, not from editable targets: a design's script can post them, so the chrome acts on them only in Edit mode, from the history frame while that frame holds focus), cd:anchor-rects { anchors: [{ id, box|null, visible|null }] } (`box` is the target's unclipped border box, `visible` that box clipped by scrolling ancestors and the frame viewport; chrome keeps them under the sending frame's id only, in any mode). Chrome → iframe (runtime accepts only from the parent it captured at load, `parseChromeFrameMessage`): cd:mode { mode: interact|comment|edit }, cd:pick-parent, cd:pick-child, cd:anchors { anchors: [{ id, selector }] } (the frame's element comments; the runtime answers with cd:anchor-rects, at most once per animation frame and only when a target moved), cd:pick-refresh (9e, Edit mode only: re-describe the current pick, selector reused, and re-post it with repost true), cd:edit-apply { sourceNumber, text } or { sourceNumber, style } (9e, Edit mode only: the live preview of the one element with that number, its whole text node or style attribute as the chrome computed it with the edit core's own value rules; display only, the runtime's one write to the design DOM; a re-posted pick keeps its announcement sequence).
6. A design's own script can post any cd:* message. Chrome renders frame data as text or geometry only (never `{@html}`). cd:pick text fields are capped (`layout.ts`) and free of control characters and line separators, except Edit mode's `edit.text` and `edit.style` (the page's own source text, shown only as field values, never put in an Agent prompt); style keys come from `COMMENT_STYLE_KEYS` and values allow only letters and digits in any script, `_`, space and `#%.,()'"/+-`. `comments.json` reuses those same guards on parse and on add. Anything that will reach an Agent prompt is sanitized again first (8h `commentPrompt`).
